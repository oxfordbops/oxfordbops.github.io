# Bops

A static page that lists and maps every college bop and formal in a university city for the next fortnight, in the spirit of talks.cam. Bops, formals and the season's balls (May Balls in Cambridge) are three tabs on one page; balls are listed until they happen, without the fortnight limit. No backend and no submission form: a Claude Code cloud routine checks college calendars, ents pages and student press every morning, keeps only what it can verify, rewrites one JSON file and pushes it.

One template, one repository per city. This repository is the city named in `city.json`.

| City | Repository | Site |
|---|---|---|
| Cambridge | `cambridgebops/cambridgebops.github.io` | https://cambridgebops.github.io/ |
| Oxford | `oxfordbops/oxfordbops.github.io` | https://oxfordbops.github.io/ |

## Layout

| Path | Role | City-specific? |
|---|---|---|
| `city.json` | Name, tagline, palette (light tokens; the page is always light), favicon colours, colleges with coordinates, map centre, student press and SU for the routine, and the GoatCounter site code for analytics (empty for none). | yes |
| `docs/events.json` | `{generated, sources, bops: [...]}`, rewritten every Sunday by the routine. Fields per entry: kind (bop, formal or ball), title, starts_at, ends_at, college, venue, host, price, guests, dress, url, details, source. | yes |
| `docs/sources.json` | The registry of verified sources: common-room and ents sites, calendars, termcards, college events pages, SU listings, student press, and each college's Instagram. The routine reads only these. | yes |
| `site/index.template.html` | The whole page: palette tokens, filter bar (When segmented control, college chips with counts), Leaflet map with a count per college, day-by-day list with the tinted "tonight" section, source link per bop. Placeholders are filled from `city.json`. | shared |
| `site/ROUTINE.template.md` | The routine's instructions. | shared |
| `docs/index.html`, `docs/ROUTINE.md` | Generated by `scripts/build.py`. Do not edit by hand; a stale build fails the tests. | generated |
| `scripts/build.py` | Renders the two generated files; `--check` verifies they are current. | shared |
| `scripts/sync_template.sh` | Copies the shared parts into another city's repository and rebuilds there. | shared |
| `scripts/collect.py` | What the weekly routine runs first: fetches every source once, follows event links, reads Google Calendars and PDFs, renders JavaScript pages, expands registry formal-hall weekdays inside Full Term, and writes a compact digest. Stdlib only. | shared |
| `scripts/check_sources.py` | Probes every registered URL and reports colleges without a working source. | shared |
| `scripts/seo.py` | Run by the deploy on the published copy: prerenders the listings into the page and writes the static pages students search for (`/bops/`, `/formals/`, the balls page, `/other-events/`, `/colleges/` and one per college), `sitemap.xml` and `robots.txt`. | shared |
| `scripts/og_image.py` | Draws the link-preview image `docs/og.png` from `city.json`; run once per city. | shared |
| `scripts/archive.py` | Moves past listings into `docs/archive/YYYY-MM.json`; the routine runs it every week. | shared |
| `scripts/stress.py` | Builds stress-test variants of the page (empty, oversized, hostile data, fixed clocks). | shared |
| `tests/` | Data contract, registry, page and build freshness. All read `city.json`. | shared |
| `.github/workflows/deploy.yml` | Checks the build, runs the tests, deploys `docs/` to GitHub Pages. | shared |

## Working on it

```bash
python3 scripts/build.py                   # after editing city.json or anything in site/
python3 -m http.server -d docs 8765        # preview (fetch needs a server)
python3 -m unittest discover -s tests      # must pass before any deploy
python3 scripts/check_sources.py           # are every college's sources still reachable?
```

To change something for every city, edit `site/` or `scripts/` or `tests/` here, then run `scripts/sync_template.sh ../<other-city-repo>` and commit in both. To change one city only, edit its `city.json` or its data files.

To change what the routine does, edit `site/ROUTINE.template.md`, rebuild and push. The routines' stored prompt only tells them to follow `docs/ROUTINE.md` in the checked-out repository, so the next run picks up the change; nothing needs pasting. Each June, add the next year's Full Term dates to `city.json` (the freshness check fails 45 days before they run out).

## Adding a city

1. Create a GitHub organization `<city>bops` and an empty repository `<city>bops.github.io` in it.
2. Copy this repository's shared files there (`scripts/sync_template.sh` into an empty folder that has a `city.json`), write `city.json` with the city's colleges, palette and press, and an empty `docs/events.json` and `docs/sources.json` with the colleges list.
3. Build the source registry (`docs/sources.json`), run `scripts/check_sources.py` until every college has a readable source, build, test, push.
4. Enable GitHub Pages with the workflow build, and create the routine from `docs/ROUTINE.md`.

## Analytics

Pageviews, source-link clicks and filter use are counted by [GoatCounter](https://www.goatcounter.com) when `city.json` names a site code under `analytics.goatcounter`: the page loads `gc.zgo.at/count.js`, which sets no cookies and sends the page path, referrer, screen size and the event names below (the page has no query strings or accounts, so nothing identifies a visitor); GoatCounter's own documentation covers what it stores. No consent banner is needed. The dashboard is at `https://<code>.goatcounter.com`. Pageviews are counted under the path `/<slug>` and events under `<slug>/filter/when/<value>`, `<slug>/filter/college/<name>`, `<slug>/bop/<host>` and `<slug>/source/<host>` for click-throughs, so several cities can share one GoatCounter site and still be told apart by path. Leave the code empty to ship the page with no analytics at all.

## Audit

A second Claude Code cloud routine per city, "<City> Bops audit", runs on the 15th of every second month (February, April, June, August, October, December) at 08:30 UTC and follows `scripts/audit_prompt.md`. It re-reads the sources independently of the daily routine and checks seven things: unreachable sources, missing or wrong listings, regular formal-hall schedules against their pages, official college pages missing from the registry, ball dates, the society list and its popularity ranking, and term dates against the university's own page. It writes its findings in the shape of `scripts/audit_schema.json`, and `scripts/audit_report.py` opens an issue labeled `audit` (or comments on the open one) and sends a push notification when something needs a person. It never edits the repository. Run it early from claude.ai/code/routines with "Run now". The freshness check (`.github/workflows/freshness.yml`) runs every morning and fails if the last run is more than 8 days old; it needs no model.

## Hosting

Served by GitHub Pages at the organization address. Pushes to `main` check the build, run the tests and deploy `docs/`. The weekly routine commits to the same repository.

## Instagram preview generator

Generate offline carousel PNGs, a deterministic caption and a manifest from the
verified listings: `python3 scripts/instagram_preview.py --date 2026-11-01`.
See [setup, artifact review and limitations](docs/INSTAGRAM_PREVIEWS.md).
This tool only creates previews; it never publishes or needs an Instagram account.
