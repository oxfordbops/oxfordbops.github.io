# Bops

A static page that lists and maps every college bop in a university city for the next fortnight, in the spirit of talks.cam. No backend and no submission form: a Claude Code cloud routine checks college calendars, ents pages and student press every morning, keeps only what it can verify, rewrites one JSON file and pushes it.

One template, one repository per city. This repository is the city named in `city.json`.

| City | Repository | Site |
|---|---|---|
| Cambridge | `cambridgebops/cambridgebops.github.io` | https://cambridgebops.github.io/ |
| Oxford | `oxfordbops/oxfordbops.github.io` | https://oxfordbops.github.io/ |

## Layout

| Path | Role | City-specific? |
|---|---|---|
| `city.json` | Name, tagline, palette (light and dark tokens), favicon colours, colleges with coordinates, map centre, student press and SU for the routine. | yes |
| `docs/events.json` | `{generated, sources, bops: [...]}`, rewritten daily by the routine. Fields per bop: title, starts_at, ends_at, college, venue, host, price, guests, dress, url, details, source. | yes |
| `docs/sources.json` | The registry of verified sources: common-room and ents sites, calendars, termcards, college events pages, SU listings, student press, and each college's Instagram. The routine reads only these. | yes |
| `site/index.template.html` | The whole page: palette tokens, filter bar (When segmented control, college chips with counts), Leaflet map with a count per college, day-by-day list with the tinted "tonight" section, source link per bop. Placeholders are filled from `city.json`. | shared |
| `site/ROUTINE.template.md` | The routine's instructions. | shared |
| `docs/index.html`, `docs/ROUTINE.md` | Generated by `scripts/build.py`. Do not edit by hand; a stale build fails the tests. | generated |
| `scripts/build.py` | Renders the two generated files; `--check` verifies they are current. | shared |
| `scripts/sync_template.sh` | Copies the shared parts into another city's repository and rebuilds there. | shared |
| `scripts/check_sources.py` | Probes every registered URL and reports colleges without a working source. | shared |
| `scripts/stress.py` | Builds stress-test variants of the page (empty, oversized, hostile data, fixed clocks, dark theme). | shared |
| `tests/` | Data contract, registry, page and build freshness. All read `city.json`. | shared |
| `.github/workflows/deploy.yml` | Checks the build, runs the tests, deploys `docs/` to GitHub Pages. | shared |

## Working on it

```bash
python3 scripts/build.py                   # after editing city.json or anything in site/
python3 -m http.server -d docs 8765        # preview (fetch needs a server)
python3 -m unittest discover -s tests      # must pass before any deploy
python3 scripts/check_sources.py           # are every college's sources still reachable?
```

To change something for every city, edit `site/` or `scripts/` or `tests/` here, then run `scripts/sync_template.sh ../<other-city-repo>` and commit in both. To change one city only, edit its `city.json` or its data files.

To change what the routine does, edit `site/ROUTINE.template.md`, rebuild, and paste the generated `docs/ROUTINE.md` (below the rule) into the routine at https://claude.ai/code/routines.

## Adding a city

1. Create a GitHub organization `<city>bops` and an empty repository `<city>bops.github.io` in it.
2. Copy this repository's shared files there (`scripts/sync_template.sh` into an empty folder that has a `city.json`), write `city.json` with the city's colleges, palette and press, and an empty `docs/events.json` and `docs/sources.json` with the colleges list.
3. Build the source registry (`docs/sources.json`), run `scripts/check_sources.py` until every college has a readable source, build, test, push.
4. Enable GitHub Pages with the workflow build, and create the routine from `docs/ROUTINE.md`.

## Hosting

Served by GitHub Pages at the organization address. Pushes to `main` check the build, run the tests and deploy `docs/`. The daily routine commits to the same repository.
